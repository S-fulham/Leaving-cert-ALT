Meeting the brief.

Basic Requirments

Requirments Requirments Met?
Embedded system design Build a functional embedded system that uses at least one digital input and at least one analogue input. The system must generate at least one primary output which can be either digital or analogue. The system can be started or calibrated manually but should operate automatically once started. Yes

Inputs
-Fire Sensor digital, returns one if no fire detected and 0 if fire detected
-Moisture Sensor analogue, returns soil moisure as a percentage.

Outputs
-LED digital, LED turns on if soil moisture low
Data collection Use your embedded system to collect and store environmental data that relates to your chosen theme. The stored data will be used as part of your model in the advanced requirements. Yes

- My embedded collects and stores temperature, soil moisture and air humidity all of which are used live in my model. (The system also collects and stores flame detection data although it is not used in the model.)
Process simulation Configure your embedded system to simulate a real-world process related to the theme (for example: canopy cover, drought cycles, biodiversity changes, population growth/decline, wildfire risk). Run tests to show how the system responds using different inputs or changing environmental data. Yes

I simulated a drought by taking out the soil moisture sensors and drying it, this system responded by turning on a red LED to let me soil moisture was low and the water pump automaticly activated.

Advanced Requirments

Requirments Requirments Met?
Disaster risk modelling: Using Python, develop a computer model of a chosen disaster risk scenario related to forests (for example: wildfire, drought, pest outbreak, air quality, landslides, flooding). Your model must use some data collected from your embedded system and can be combined with open-source data or simulated data. Yes - I chose to model wildfire and modeled the chance of a fire starting/spreading based on data gathered from my Microbit and data from online data sets (temperature, moisture level, distance between trees, air humidity)
What-if simulations: Explore how your forest disaster risk model behaves under different conditions by creating and testing two "what-if" scenario simulations. Each scenario should involve changing one or more key variables and observing the resulting changes in system behaviour or predicted risk. Examples: What if temperature increases (drought conditions)? What if rainfall decreases (drought conditions)? What if tree density increases (afforestation)? What if the forest canopy is reduced (deforestation)? What if a species population grows too large or too small (for example: too many predators or too few pollinators)? What if high temperatures and low soil moisture increase wildfire risk? Yes - My model looks at a 2 variables moisture levels (drought conditions) and temperature levels.
Adaptive system: Extend your system to include a feedback mechanism that enables it to adapt automatically to changing conditions (for example: triggering an alert when fire risk is high, watering a plant when soil moisture is too low, or adjusting predictions based on the most recent data). Note that the adaptive response can be either physical (extending the embedded system) or virtual (changing the model so that it adjusts automatically). Yes - My system includes multiple responses depending on the data recieved by the sensors including water pump turning on if fire is detected and not turning off until the fire is no longer detected, water pump turning on for three seconds if moisture level is low, LED turning on if temperature is high.
